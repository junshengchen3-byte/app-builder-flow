# Implementation Outputs

Use these output shapes so the user can approve decisions and another engineer can execute without guessing.

## Product Plan

Include:

- Summary
- Target user
- Core use cases
- MVP features
- Non-goals
- Platforms
- Risks and blockers
- Default decisions

## UX Flow

Include:

- Entry points
- Main happy path
- Alternate paths
- Empty states
- Error states
- Permission states
- Settings or account surfaces

## UI Direction

Include:

- Visual reference and adaptation rules
- Color and typography direction
- Screen-level layout notes
- Component behavior
- Responsive requirements
- Accessibility constraints when relevant

## Technical Plan

Include:

- Client stack
- Backend decision
- Data model
- API/interface shape if backend exists
- Local persistence strategy
- Permissions and platform capabilities
- Build/test commands

## Implementation Report

Include:

- What changed
- Files or modules touched when relevant
- Verification performed
- Known gaps
- Next step

## Blocker Report

For each blocker, include:

- Blocker
- Cause
- Owner
- Impact
- Recommended handling

## Release Checklist

Include:

- App identity
- Icons and screenshots
- Privacy disclosures
- Permission strings
- Signing/account status
- Store submission path
- Manual acceptance checklist
